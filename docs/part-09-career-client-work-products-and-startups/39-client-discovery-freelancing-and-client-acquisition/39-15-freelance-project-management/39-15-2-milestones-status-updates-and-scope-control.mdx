Projects fail slowly through untracked drift, not sudden explosions. This lesson teaches you the lightweight control system that keeps scope, schedule, and budget visible to both sides — so surprises never threaten the relationship.

## 1. The Milestone Map

Break the engagement into 2–4 milestones tied to outcomes, not activities. Example: M1 — policy ingestion + RAG answers with citations; M2 — eval harness ≥0.85 recall@3; M3 — deploy + staff training. Each milestone = demo + invoice checkpoint.

## 2. The Friday Status Report (Copy Template)

```
Week of 2026-12-08
Done: RAG ingestion complete; 35/40 eval cases passing
In progress: Citation reliability pass (Blocked: none)
Next: Eval threshold + deploy to staging
Metrics: Retrieval p95 800ms; eval recall@3 = 0.87
Risks: None new; note doc gap on shipping policy (see below)
```

## 3. Scope Control

Change request, not verbal scope creep: "Yes, we can add X; it adds 3 days and $1,200 — confirm and I'll update the timeline." Always written; always paid or time-boxed; never absorbed silently.

## 4. Common Failure Modes

- **Milestones tied to effort** — "setup env" means nothing; tie to outcomes.
- **No metrics in reports** — clients can't tell if you're winning; show numbers.
- **No change control** — scope creep bleeds margin on every engagement.

**Acceptance criteria.** Your map: each milestone has a demoable outcome, a test, and a payment; change-order language included.
