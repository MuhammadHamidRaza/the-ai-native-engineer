Python syntax is intentionally clean—using indentation (`4 spaces`) instead of braces—but Python's **data model** hides two traps for developers coming from JavaScript or C: **every variable is a name pointing to an object**, and **mutable defaults in function signatures persist across calls**. Subchapter **09.1** locks down Python's core data structures, iteration tools, and file basics cleanly.

## Lessons in Subchapter 09.1

1. **[09.1.1 Objects, References and Mutability](/book/part-03-python-development/09-python-fundamentals-deep/09-1-core-syntax-and-data-model/09-1-1-objects-references-and-mutability):** Indentation rules, primitives, f-strings, `None` + `is` vs `==`, object identity, mutability, shallow/deep copying, and the mutable default argument bug (`items=[]`).
2. **[09.1.2 Lists, Tuples, Dicts and Sets](/book/part-03-python-development/09-python-fundamentals-deep/09-1-core-syntax-and-data-model/09-1-2-lists-tuples-dicts-and-sets):** Choosing the right built-in collection, `.get()` safety, hashability rules, slicing, and lookup complexity.
3. **[09.1.3 Control Flow, Comprehensions and Generators](/book/part-03-python-development/09-python-fundamentals-deep/09-1-core-syntax-and-data-model/09-1-3-control-flow-comprehensions-and-generators):** `if/elif/else`, `for`, `enumerate`, `zip`, comprehensions, lazy `yield` generators, and safe `with open(...)` file reading/writing.
