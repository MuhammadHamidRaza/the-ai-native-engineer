Picking the right collection turns O(n^2) sluggish loops into crisp O(n) scripts and prevents `KeyError` crashes at runtime.

## 1. Python's Four Core Collections Compared

| Collection | Ordered? | Mutable? | Typical Use Case | Lookup (`in` / key) |
| :--- | :---: | :---: | :--- | :---: |
| **`list`** (`[1, 2]`) | Yes | Yes | Sequences, stacks, queues | O(n) scan |
| **`tuple`** (`(1, 2)`) | Yes | **No** | Fixed records, dict keys, multiple returns | O(n) scan |
| **`dict`** (`{"a": 1}`) | Yes (insertion) | Yes | Key-value maps, JSON objects, frequency counts | **O(1) hash** |
| **`set`** (`{"a", "b"}`) | No | Yes | Deduplication, fast membership, intersections | **O(1) hash** |

## 2. Safe Indexing, Slicing, and `.get()`

```python
items = ["alpha", "beta", "gamma", "delta"]
print(items[-1])     # "delta" (last item)
print(items[1:3])    # ['beta', 'gamma'] (slicing creates a shallow copy)

user = {"id": "u1", "email": "ada@example.com"}
# SAFE lookup: returns "member" if "role" missing instead of raising KeyError!
role = user.get("role", "member")
print("Role:", role)

# Unpacking dict items cleanly
for key, value in user.items():
    print(f"{key} -> {value}")
```

**Hashability Rule:** Keys inside a `dict` and items inside a `set` **must be immutable (hashable)**—strings, ints, and tuples of strings work; lists and dicts raise `TypeError: unhashable type: 'list'`. Also watch out: `{}` creates an **empty dict**, whereas an empty set requires `set()`.

## 3. Fast Membership Check (`set` vs. `list`)

Checking `if user_id in allowed_ids:` across 50,000 IDs inside a loop runs ~1,000x faster when `allowed_ids` is a `set` (`O(1)`) rather than a `list` (`O(n)`).

- [ ] Chooses `set` for deduplication and frequent `x in collection` checks.
