One agent producing an answer is a claim. Two agents checking each other is (sometimes) evidence. This section is about the machinery that makes multi-agent output trustworthy — and about the loops that make it worse when built naively.

## The Core Loop

```text
generate --> evaluate --> (pass) --> publish
   ^            |
   |        (fail) --> feedback --> regenerate
   +------------------- max 3 iterations -------------------┘
```

The evaluator can be an LLM critic, a deterministic verifier (schema check, test suite, policy rule), a retrieval-grounding check, or a human. The **stop conditions are the design**: pass the rubric, or hit the iteration cap, or exhaust the budget — never "until it feels done".

## Why Verification Is Not Optional Above One Agent

A single agent's failure is visible: it's wrong, you catch it. A multi-agent system's failure is often *agreeable*: agents confirming each other's errors with confidence. Verification patterns restore an independent vantage point — a critic who sees different evidence, a deterministic check the model cannot argue with, a human at the irreversible edge.
