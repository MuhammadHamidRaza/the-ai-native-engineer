Chapter 30 built the Postmaster as code. Chapter 31 hardened it with tools, state and guardrails. Chapter 32 gave it a protocol. This chapter steps sideways: **n8n** — a visual, node-based automation platform that lets ShopCore connect SaaS tools and LLMs into reliable, scheduled business workflows without hand-writing every integration. It is where "glue work" (new refund-dispute email arrives → LLM classifies → Slack notice or a tracked ticket) becomes a reviewable, versioned, retryable artifact instead of a cron job someone forgot about.

**n8n** (pronounced "nodemation") is a fair-code, source-available workflow automation tool aimed at technical teams: it is self-hostable, it speaks JavaScript natively inside nodes, and it has first-class AI node support. It is not no-everything — think of it as low-code with an escape hatch to real code. ShopCore uses it for the operations layer: the Postmaster's *inputs* and *outputs*, not its reasoning core.

## What You Will Build in This Chapter

The running example is the **ShopCore refund-dispute pipeline**, the same case the Postmaster handles in Chapters 29–32, here implemented as an automation:

1. A new customer email about a disputed charge arrives in the support mailbox.
2. An n8n workflow triggers, parses and classifies it with an LLM (auto-resolvable vs must-escalate).
3. Auto-resolvable disputes post a Slack notice to `#support-ops` with the order ID; everything else opens a tracked ticket in Linear/Notion with the LLM's summary attached.
4. Every step is logged, retried on transient failure, and routed to an error workflow when something breaks permanently.

By the end of the chapter you will have installed n8n, built this pipeline, connected OpenAI/Anthropic/Google models, and self-hosted the result behind HTTPS with backups.

## Who n8n Is For — and Who It Is Not For

| You should reach for n8n when | Reach for code instead when |
| :-- | :-- |
| Integrating 3+ SaaS tools with moderate logic | Core business logic belongs in your service layer, tested with your stack |
| Ops/RevOps-style automations owned by one team | You need sub-100ms latency or heavy transactional guarantees |
| You want LLM steps inside a deterministic flow | The agent loop *is* the product (then Chapter 30's SDK path wins) |
| You want self-hosting and no per-task pricing | You need guaranteed cross-region HA without operating infrastructure |
