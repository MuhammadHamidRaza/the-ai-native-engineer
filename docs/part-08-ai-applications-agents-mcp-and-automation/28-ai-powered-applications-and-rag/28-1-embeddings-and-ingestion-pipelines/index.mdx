Before HelpBot can answer anything, ShopCore's six policy PDFs must pass through an **ingestion pipeline**: a repeatable, re-runnable job that parses documents into clean text, splits them into chunks, embeds each chunk, and stores vectors plus metadata where a retriever can filter them in milliseconds. This section is where most RAG projects quietly succeed or fail — no model can recover a fact that never survived parsing.

## Pipeline Stages

1. **Parse** — PDF/DOCX/HTML/Markdown to text, preserving headings, page numbers, tables (28.1.1).
2. **Chunk** — split text into embedding-sized units with overlap and structure metadata (28.1.1).
3. **Embed** — call `text-embedding-3-small` (1536 dims) or `text-embedding-3-large` (3072 dims), verified Nov 2026 (28.1.2).
4. **Index & Filter** — store vectors in Postgres + pgvector (default) or a dedicated vector DB, with metadata for `doc_type`, `effective_date`, `access_tier` (28.1.2).

```text
returns.pdf ─► parser ─► [{text, page, heading_path}] ─► chunker
                                                            │
              vector index ◄── upsert ◄── embedder ◄── chunks
                    │
              filtered similarity search (doc_type, effective_date >= today-2y)
```
