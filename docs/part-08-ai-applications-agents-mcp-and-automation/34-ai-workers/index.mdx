Chapters 29–33 gave ShopCore an agent (the Postmaster) and the plumbing to run automations. This chapter is about the operational middle layer: **AI workers** — bounded-role, always-on, auditable automation roles that own a real business process end-to-end. Not a chatbot your team talks to. Not a script that silently rots. A worker has a mission, inputs, guardrails, a budget, an SLA, an owner, a kill-switch, and a paper trail.

## Worker vs Agent vs Automation — the Honest Distinction

| | Automation (33) | Agent (30) | AI Worker (34) |
| :-- | :-- | :-- | :-- |
| Scope | One workflow, deterministic | One reasoning loop, general tools | One **job role**, ongoing, owns an outcome |
| Lifespan | Per execution | Per conversation/task | Weeks–months, versioned like a service |
| State | None / per-run | Session memory | Durable queue + audit log + run history |
| Accountability | "The flow ran" | "The agent answered" | An SLA, an error budget, an owner, a kill-switch |
| Example | New order → Slack | Postmaster triage in a chat | **AR Nudge worker** chasing overdue invoices for 90 days |

Every worker in this chapter is built on the n8n + LLM + Postgres substrate from Chapter 33 — this is where the visual canvas becomes a staffed operation. The three ShopCore workers:

- **Inbox Triage worker** — new support email → classify → draft response grounded in Ch 28 policy docs → approval gate → send or escalate.
- **AR Nudge worker** — invoice 7 days overdue → tone-laddered reminder sequence (day 1 → 7 → 14 → 21), stopping on payment, dispute or max touches.
- **Research Brief worker** — weekly cron → competitor list in → cited Notion page out, for leadership Monday mornings.

## The Rules That Apply to Every Worker

1. **Red line:** no worker sends anything customer-facing without a passing approval gate (or an explicit, logged "auto-approve" policy with dollar/sentiment limits).
2. **Every decision is logged**: input hash, prompt version, model version, output, approver, latency — schema in 34.2.2.
3. **Kill-switch first**: each worker can be disabled in under 60 seconds by its owner, no deploy required.
4. **Budget**: a monthly token/API cap with a hard stop, alerting at 70%.
5. **Honest ROI**: measure hours saved, error rate, and escalation volume — not tokens generated.
