This section is where the blueprint becomes a repository. Two lessons, two disciplines: shipping the deterministic spine first, then adding — only if justified — an agent with named guardrails and real evals.

## Lessons in Subchapter 42.2

1. **[42.2.1 Building the Core Application and Backend Services](/book/part-10-integrated-capstone/42-from-real-problem-to-production-product/42-2-full-stack-and-ai-implementation/42-2-1-building-the-core-application-and-backend-services):** Vertical slices, the reference implementation under `examples/chapterhouse-capstone/`, migrations, seeds, messy-CSV handling, and the one-command-to-run rule.
2. **[42.2.2 Integrating Agents, MCP Tools and Guardrails](/book/part-10-integrated-capstone/42-from-real-problem-to-production-product/42-2-full-stack-and-ai-implementation/42-2-2-integrating-agents-mcp-tools-and-guardrails):** The agent decision tree, when (and only when) MCP is justified, guardrails that actually block, and an eval set that survives prompt tweaks.

## How to Use This Subchapter

Build in the order given. Resist the pull to "start with the agent". The deterministic spine proves your architecture; the agent is seasoning, not the meal.
