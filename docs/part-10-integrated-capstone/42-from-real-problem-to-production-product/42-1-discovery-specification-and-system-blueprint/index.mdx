The capstone is not a coding exercise — it's a **delivery rehearsal**. This section covers the two disciplines that make delivery possible before any code exists: finding a problem worth solving, and designing a system that solves it without gold-plating.

## Lessons in Subchapter 42.1

1. **[42.1.1 Identifying a Real Business Problem](/book/part-10-integrated-capstone/42-from-real-problem-to-production-product/42-1-discovery-specification-and-system-blueprint/42-1-1-identifying-a-real-business-problem):** What "real" means — measurable pain, an owner, a bounded scope — and how to source, interview, and validate one in days, not weeks.
2. **[42.1.2 Architecture, Data Model and AI Agent Spec](/book/part-10-integrated-capstone/42-from-real-problem-to-production-product/42-1-discovery-specification-and-system-blueprint/42-1-2-architecture-data-model-and-ai-agent-spec):** The decision tree for whether AI is justified at all, schema-first design, API surface minimalism, and writing an honest agent spec (or an honest "no agent" verdict).

## How to Use This Subchapter

Complete both lessons before writing any code. The capstone punishes builders who skip discovery — every subsequent week commits you to code that would have changed had you talked to users first.
