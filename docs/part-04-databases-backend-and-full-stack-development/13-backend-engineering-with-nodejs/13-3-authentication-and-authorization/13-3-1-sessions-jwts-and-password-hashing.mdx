Two security rules allow zero compromise: **never store or log plaintext passwords**, and **never store session credentials where browser XSS scripts can steal them (`localStorage`)**.

## 1. Password Hashing with Built-In `crypto.scrypt` (or `argon2`)

Fast hashes like MD5 or SHA-256 can be brute-forced at billions of guesses per second on GPUs. Always use a **slow, memory-hard, salted key-derivation function** (`argon2id` via `argon2` package, or Node's built-in `crypto.scrypt` with per-user random salts and timing-safe comparison):

```javascript
import { randomBytes, scrypt, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';

const scryptAsync = promisify(scrypt);

export async function hashPassword(password) {
  const salt = randomBytes(16).toString('hex');
  const derived = await scryptAsync(password, salt, 64);
  return `${salt}:${derived.toString('hex')}`;
}

export async function verifyPassword(password, storedHash) {
  const [salt, keyHex] = storedHash.split(':');
  if (!salt || !keyHex) return false;
  const expected = Buffer.from(keyHex, 'hex');
  const actual = await scryptAsync(password, salt, 64);
  return expected.length === actual.length && timingSafeEqual(expected, actual);
}
```

## 2. Server Cookie Sessions vs. JWTs & CSRF

- **Opaque Session ID in Cookie (Recommended default for web apps):** Store a random session token (`sessions` table or Redis), send the ID in an **`HttpOnly; Secure; SameSite=Lax`** cookie (`HttpOnly` blocks `document.cookie` XSS theft; `SameSite=Lax` blocks cross-site `POST` CSRF). Revoking a compromised user or logging out deletes the server row immediately!
- **Signed JWT (`Bearer` or Cookie):** Remember JWT payloads are **Base64-encoded, NOT encrypted**—anyone can decode claims (`sub`, `role`), so never put secrets inside a JWT! If using JWTs, keep access tokens short-lived (`15m`), rotate refresh tokens on the server, and always specify allowed algorithms explicitly when verifying.
- **CSRF Defense-in-Depth:** Beyond `SameSite=Lax`, verify `Origin` / `Referer` headers match your app domain on state-changing requests (`POST`/`PATCH`/`DELETE`), or require a custom CSRF header.

## Mastery Checklist

- [ ] Hashes passwords with `argon2` or salted `scrypt` + `timingSafeEqual` (never SHA-256).
- [ ] Stores web auth tokens in `HttpOnly; Secure; SameSite=Lax` cookies rather than `localStorage`.
