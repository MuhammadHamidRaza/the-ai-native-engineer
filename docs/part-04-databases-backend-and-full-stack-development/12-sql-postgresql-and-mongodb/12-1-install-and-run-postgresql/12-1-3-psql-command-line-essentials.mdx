psql is PostgreSQL's official terminal client: free, scriptable, and the tool every migration, backup and deploy actually uses. You already know the GUI side from [12.1.2](/book/part-04-databases-backend-and-full-stack-development/12-sql-postgresql-and-mongodb/12-1-install-and-run-postgresql/12-1-2-pgadmin-4-from-zero); here is the same power from a shell prompt.

## 1. Opening psql — Where Do These Commands Run?

All commands below run in a **new** terminal window (PowerShell on Windows, Terminal on macOS/Linux). Never inside pgAdmin.

```bash
psql -U postgres -h localhost -p 5432 -d postgres
```

- `-U postgres` — connect as the `postgres` role.
- `-h localhost` — force a TCP connection (same path your app uses). Use `-h /var/run/postgresql` or omit on Linux for the socket.
- `-p 5432` — the port; adjust if you changed it during install.
- `-d postgres` — start in the `postgres` database (you must start somewhere).

Expected: a password prompt, then the `postgres=#` prompt. If you get an error, stop here and fix [12.1.1 step 6/troubleshooting](/book/part-04-databases-backend-and-full-stack-development/12-sql-postgresql-and-mongodb/12-1-install-and-run-postgresql/12-1-1-what-postgresql-is-and-how-to-install-it) first.

## 2. The Seven Backslash Commands You Will Use Daily

psql has its own mini-language, all starting with `\` (backslash). These are **psql commands**, not SQL — no semicolon needed, no `\g` required.

| Command | Shows | Example output |
| :-- | :-- | :-- |
| `\l` | List all databases | `shopcore`, `postgres`, `template0`... |
| `\c shopcore` | Connect to `shopcore` | `You are now connected to database "shopcore" as user "postgres".` |
| `\dt` | List tables in current DB | `order_items`, `orders`, `payments`, `products`, ... |
| `\d products` | Columns, types, indexes of `products` | Shows `category_id`, FKs, `idx_products_category_id`... |
| `\du` | List roles/users | `postgres  Superuser  ...` |
| `\di` | List indexes | `idx_orders_user_id`... |
| `\q` | Quit | shell prompt returns |

Try now: `\l` then `\c shopcore` then `\dt`. You should see the 6 ShopCore tables. Then `\d categories` and compare every column, type and constraint with [11.1.3](/book/part-04-databases-backend-and-full-stack-development/11-database-design-and-fundamentals/11-1-data-modeling-and-relationships/11-1-3-the-shopcore-schema) — they must match exactly.

## 3. Running SQL and .sql Files

### Inline SQL

```sql
SELECT sku, title, price_cents FROM products ORDER BY price_cents;
```

End SQL statements with `;` — without it, psql waits on the next line (`postgres-#`) for the rest of your command, a classic beginner confusion. Press `Ctrl+C` to cancel and start the statement again.

### Running a file from disk

Save the canonical DDL/seed as `shopcore_schema.sql` and `shopcore_seed.sql` next to each other (from 11.1.3), then:

```bash
createdb -U postgres -h localhost shopcore
psql -U postgres -h localhost -d shopcore -f shopcore_schema.sql
psql -U postgres -h localhost -d shopcore -f shopcore_seed.sql
```

`-f` prints each statement and its result; a failing statement does **not** stop the script by default — scroll the output and read every `ERROR`/`psql:file.sql:LINE:`. (Use `psql ... -v ON_ERROR_STOP=1 -f file.sql` in scripts so the first error aborts everything.)

Inside psql, the twin is `\i shopcore_seed.sql`.

### Measuring with `\timing`

```sql
\timing on
SELECT count(*) FROM order_items;
```

Prints execution time after each statement — handy sanity check for slow queries later (Chapter 12.2.3).

## 4. Piping and Scripting (Why Pros Love psql)

Because psql is a normal program, it composes with shells:

```bash
# Export a query result to CSV — file opens fine in Excel/Google Sheets
psql -U postgres -h localhost -d shopcore -c "SELECT * FROM products;" --csv > products.csv

# Run a .sql file and fail loudly on error — perfect for CI
psql -U postgres -h localhost -v ON_ERROR_STOP=1 -d shopcore -f migrate.sql
```

## 5. Verifying a Database from Scratch — the Complete Cycle

This sequence is exactly how CI and migration tools prove a database works. Run it once by hand:

```bash
dropdb   -U postgres -h localhost --if-exists shopcore_verify
createdb -U postgres -h localhost shopcore_verify
psql     -U postgres -h localhost -v ON_ERROR_STOP=1 -d shopcore_verify -f shopcore_schema.sql
psql     -U postgres -h localhost -v ON_ERROR_STOP=1 -d shopcore_verify -f shopcore_seed.sql
psql     -U postgres -h localhost -d shopcore_verify -c "SELECT count(*) FROM products;"
```

Expect `3`. If anything fails, the `\echo`-free error text tells you the file and line. Drop the verify database when done.

## 6. Troubleshooting

| Symptom | Fix |
| :-- | :-- |
| Stuck at `postgres-#` | Unterminated statement/quote — `Ctrl+C`, retype with final `;` |
| `\dt Did not find any relations` | You are in the wrong DB — run `\c shopcore` |
| `psql: FATAL: database "shopcore" does not exist` | Create it: `createdb -U postgres -h localhost shopcore` |
| Statement ran but printed `0 rows` | Fine for `UPDATE`/`DELETE` that matched nothing — but check your `WHERE` |
| File path with spaces fails on Windows | Quote it: `psql ... -f "C:\books\my sql\shopcore_seed.sql"` |
| `permission denied for table users` | You connected as a non-owner role — connect as `postgres` or grant privileges (see 12.3.2) |
| Hangs after password entered | Windows service stopped — `Get-Service postgresql*`, start it |

Drop `shopcore_lab` when finished.

**Independent exercise.** Export `SELECT o.id, u.email, o.status FROM orders o JOIN users u ON u.id = o.user_id;` to `orders.csv` with `--csv`, open the file and confirm the 3 seeded rows.
