Milestone 4: the security spine. Everything you learned in 13.3 gets wired into ShopCore — registration, login, logout, `GET /auth/me`, sessions in Postgres, `HttpOnly` cookies, and the customer/admin role split. After this lesson, the store knows who its users are.

## 1. Schema Addition — Migration 003

```sql
-- 003_sessions.sql
BEGIN;
CREATE TABLE sessions (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id     BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash  TEXT NOT NULL UNIQUE,     -- sha256(token); the cookie holds the raw token
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  expires_at  TIMESTAMPTZ NOT NULL
);
CREATE INDEX idx_sessions_user_id ON sessions (user_id);
CREATE INDEX idx_sessions_expiry  ON sessions (expires_at);
INSERT INTO schema_migrations (version) VALUES ('003_sessions') ON CONFLICT DO NOTHING;
COMMIT;
```

Apply it like 15.1.2: `psql -v ON_ERROR_STOP=1 -f 003_sessions.sql shopcore`.

## 2. Crypto and Session Helpers

**`src/lib/crypto.js`** — scrypt hash/verify (same as 13.3.1):

```javascript
import { randomBytes, scrypt, timingSafeEqual, createHash } from 'node:crypto';
import { promisify } from 'node:util';
const scryptAsync = promisify(scrypt);

export async function hashPassword(password) {
  const salt = randomBytes(16).toString('hex');
  const derived = await scryptAsync(password, salt, 64);
  return `${salt}:${derived.toString('hex')}`;
}

export async function verifyPassword(password, stored) {
  const [salt, keyHex] = stored.split(':');
  if (!salt || !keyHex) return false;
  const actual = await scryptAsync(password, salt, 64);
  const expected = Buffer.from(keyHex, 'hex');
  return expected.length === actual.length && timingSafeEqual(expected, actual);
}

export const sha256 = (s) => createHash('sha256').update(s).digest('hex');
```

**`src/lib/session.js`**:

```javascript
import { randomBytes } from 'node:crypto';
import { sha256 } from './crypto.js';
import { pool } from '../db/pool.js';

export async function createSession(userId, ttlDays = 7) {
  const token = randomBytes(32).toString('base64url');
  const expires = new Date(Date.now() + ttlDays * 86_400_000);
  await pool.query(
    'INSERT INTO sessions (user_id, token_hash, expires_at) VALUES ($1, $2, $3)',
    [userId, sha256(token), expires]
  );
  return token;   // goes into the cookie; the DB stores only its hash
}

export async function findSession(token) {
  const { rows } = await pool.query(
    `SELECT s.user_id, u.email, u.full_name, u.role
     FROM sessions s JOIN users u ON u.id = s.user_id
     WHERE s.token_hash = $1 AND s.expires_at > NOW()`,
    [sha256(token)]
  );
  return rows[0] ?? null;
}

export async function destroySession(token) {
  await pool.query('DELETE FROM sessions WHERE token_hash = $1', [sha256(token)]);
}
```

## 3. Auth Routes — `src/routes/auth.js`

```javascript
import { Router } from 'express';
import { z } from 'zod';
import { pool } from '../db/pool.js';
import { hashPassword, verifyPassword } from '../lib/crypto.js';
import { createSession, findSession, destroySession } from '../lib/session.js';
import { validateBody } from '../middleware/validate.js';
import { AppError } from '../lib/errors.js';

const cookieOpts = {
  httpOnly: true,
  sameSite: 'lax',
  secure: process.env.NODE_ENV === 'production',
  maxAge: 7 * 86_400_000,
  path: '/',
};

const registerSchema = z.object({
  email: z.email().max(254),
  full_name: z.string().min(2).max(120),
  password: z.string().min(10, 'at least 10 characters').max(200),
});

const loginSchema = z.object({
  email: z.email(),
  password: z.string().min(1),
});

export const authRouter = Router();

authRouter.post('/register', validateBody(registerSchema), async (req, res, next) => {
  try {
    const { email, full_name, password } = req.body;
    const hash = await hashPassword(password);
    const { rows } = await pool.query(
      `INSERT INTO users (email, full_name, role, password_hash)
       VALUES ($1, $2, 'customer', $3)
       RETURNING id, email, full_name, role`,
      [email.toLowerCase(), full_name, hash]
    ).catch((err) => {
      if (err.code === '23505') throw new AppError(409, 'EMAIL_TAKEN', 'email already registered');
      throw err;
    });
    const user = rows[0];
    const token = await createSession(user.id, Number(process.env.SESSION_TTL_DAYS ?? 7));
    res.cookie('session', token, cookieOpts).status(201).json({ user });
  } catch (err) { next(err); }
});

authRouter.post('/login', validateBody(loginSchema), async (req, res, next) => {
  try {
    const { email, password } = req.body;
    const { rows } = await pool.query(
      'SELECT id, email, full_name, role, password_hash FROM users WHERE email = $1',
      [email.toLowerCase()]
    );
    const user = rows[0];
    if (!user || !(await verifyPassword(password, user.password_hash ?? ''))) {
      throw new AppError(401, 'BAD_CREDENTIALS', 'invalid email or password');
    }
    const token = await createSession(user.id, Number(process.env.SESSION_TTL_DAYS ?? 7));
    const { password_hash, ...safe } = user;
    res.cookie('session', token, cookieOpts).json({ user: safe });
  } catch (err) { next(err); }
});

authRouter.post('/logout', async (req, res, next) => {
  try {
    const token = req.cookies?.session;
    if (token) await destroySession(token);
    res.clearCookie('session', cookieOpts).status(204).end();
  } catch (err) { next(err); }
});

authRouter.get('/me', async (req, res, next) => {
  try {
    const token = req.cookies?.session;
    const user = token && await findSession(token);
    if (!user) return res.status(401).json({ error: 'UNAUTHORIZED' });
    res.json({ user });
  } catch (err) { next(err); }
});
```

Mount in `app.js`: `app.use('/api/v1/auth', authRouter);` (before the 404 handler).

## 4. Middleware — `src/middleware/requireAuth.js` and `requireRole.js`

```javascript
// requireAuth.js
import { findSession } from '../lib/session.js';
export async function requireAuth(req, res, next) {
  const token = req.cookies?.session;
  const user = token && await findSession(token).catch(() => null);
  if (!user) return res.status(401).json({ error: 'UNAUTHORIZED', message: 'log in first' });
  req.user = user;
  next();
}

// requireRole.js
export const requireRole = (...roles) => (req, res, next) => {
  if (!req.user) return res.status(401).json({ error: 'UNAUTHORIZED' });
  if (!roles.includes(req.user.role)) return res.status(403).json({ error: 'FORBIDDEN' });
  next();
};
```

## 5. Verify the Full Flow — curl With Expected Output

```bash
# register YOUR OWN fresh demo account — the seed already contains ada@example.com,
# so registering that exact address would fail with 409 EMAIL_TAKEN (by design).
curl -c jar.txt -X POST http://localhost:4000/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"ada-learner@example.com","full_name":"Ada Learner","password":"correct horse battery staple"}'
# -> 201 {"user":{"id":<n>,"email":"ada-learner@example.com",...}}   (cookie saved in jar.txt)

# who am I?
curl -b jar.txt http://localhost:4000/api/v1/auth/me
# -> {"user":{"user_id":<n>,"email":"ada-learner@example.com","role":"customer",...}}

# log out, /me becomes 401
curl -b jar.txt -c jar.txt -X POST http://localhost:4000/api/v1/auth/logout
curl -b jar.txt http://localhost:4000/api/v1/auth/me

# seeded users (see 11.1.3 §4) ship with **public demo passwords** so the login and
# E2E flows work out of the box — ada@example.com / `correct horse battery staple` (customer),
# linus@example.com / `linus-demo-password-1` (admin). These credentials are for local
# learning and CI ONLY. Replace them with your own before any real deployment.
curl -c jar.txt -X POST http://localhost:4000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"ada@example.com","password":"correct horse battery staple"}'
# -> 200 {"user":{"id":1,"email":"ada@example.com","role":"customer",...}}

curl -c admin.txt -X POST http://localhost:4000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"linus@example.com","password":"linus-demo-password-1"}'
# -> 200 {"user":{"id":3,"email":"linus@example.com","role":"admin",...}}
```

## 6. Common Mistakes

| Mistake | Consequence | Fix |
| :-- | :-- | :-- |
| Storing raw token in DB | DB leak = session hijack for every user | `sha256(token)` only — implemented above |
| `password` in JSON response | Leak | Destructure it out (done in `/login`) |
| Role checks on frontend only | "Admin button hidden" = no security | `requireRole('admin')` on the server route |
| `SESSION_TTL_DAYS` ignored | Tokens live forever | Honor it in `createSession` |
| Reusing the same cookie name for everything | Conflicts across apps | `shopcore_session` in shared domains |

**Assessment checklist**

- [ ] Sessions live in Postgres, hashed; raw tokens only in `HttpOnly` cookies.
- [ ] Passwords are scrypt-hashed; `timingSafeEqual` compares.
- [ ] I verified register/login/logout/me in curl end to end.
- [ ] Role guard works: 401 anonymous, 403 wrong role, 200 admin.
- [ ] `.env` secrets never committed; `.env.example` documents them.
