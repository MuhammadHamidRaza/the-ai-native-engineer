**Subchapter 14.2** is how real teams use Git: GitHub Flow (short-lived branches + pull requests), branch protection, merge vs rebase, lockfile conflict rules, and commit conventions that keep history readable and releases sane.

## Lessons in Subchapter 14.2

1. **[14.2.1 Pull Requests, Rebasing and Conflict Resolution](/book/part-04-databases-backend-and-full-stack-development/14-git-teamwork-testing-and-code-review/14-2-collaborative-git-workflows/14-2-1-pull-requests-rebasing-and-conflict-resolution):** The ticket→branch→PR→CI→review→squash loop, `git rebase` vs `merge`, and conflict surgery.
2. **[14.2.2 Commit Conventions and Release Hygiene](/book/part-04-databases-backend-and-full-stack-development/14-git-teamwork-testing-and-code-review/14-2-collaborative-git-workflows/14-2-2-commit-conventions-and-release-hygiene):** Conventional Commits, SemVer discipline, changelogs and clean histories.

Prerequisite: 14.1 — you need working Git and a GitHub account before reading this.
