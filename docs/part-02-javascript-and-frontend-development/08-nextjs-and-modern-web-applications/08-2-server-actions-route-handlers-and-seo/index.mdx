Subchapter **08.2** turns Next.js into a complete web application layer: handling HTTP requests and form mutations securely with **Route Handlers** and **Server Actions**, managing server-only `.env` secrets safely, configuring **Metadata, Fonts, and `next/image`**, placing lightweight checks in **Middleware**, and running clean **production builds (`next build` + `next start`)**.

## Lessons in Subchapter 08.2

1. **[08.2.1 API Routes and Server Mutations](/book/part-02-javascript-and-frontend-development/08-nextjs-and-modern-web-applications/08-2-server-actions-route-handlers-and-seo/08-2-1-api-routes-and-server-mutations):** `app/api/.../route.ts` endpoints, `"use server"` Server Actions with Zod + `revalidatePath`, and server-only `.env` vs. `NEXT_PUBLIC_`.
2. **[08.2.2 Metadata, Fonts and Asset Optimization](/book/part-02-javascript-and-frontend-development/08-nextjs-and-modern-web-applications/08-2-server-actions-route-handlers-and-seo/08-2-2-metadata-fonts-and-asset-optimization):** Static & dynamic SEO metadata, `next/font`, `next/image` layout-shift prevention, and `remotePatterns`.
3. **[08.2.3 Middleware and Edge Considerations](/book/part-02-javascript-and-frontend-development/08-nextjs-and-modern-web-applications/08-2-server-actions-route-handlers-and-seo/08-2-3-middleware-and-edge-considerations):** Lightweight request routing/headers, why heavy DB auth checks don't belong solely in middleware, production `next build` + `next start`, and deployment considerations.
