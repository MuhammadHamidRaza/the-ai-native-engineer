Two CSS surprises frustrate beginners almost immediately: adding `padding: 20px` makes a `width: 300px` card suddenly overflow its container (`340px`), and writing a new class rule appears to do nothing because an older selector beat it. Both surprises trace straight back to the **Box Model** and **Specificity**.

## 1. Linking CSS and the `border-box` Reset

Create `styles.css`, link it inside `<head>` with `<link rel="stylesheet" href="./styles.css" />`, and start every stylesheet with:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

**Why this matters:** By default (`content-box`), `width: 300px` sets only the *inner content box*, so adding `padding: 16px` and `border: 2px` inflates total width to `336px`! Setting **`box-sizing: border-box`** makes `width` include content + padding + border—so two `50%` columns fit side-by-side cleanly without overflowing.

```text
+----------------- Margin (outer space around box) -----------------+
|  +--------------- Border (visible edge) -----------------------+  |
|  |  +------------- Padding (inner breathing room) ----------+  |  |
|  |  |               Content (text / image)                  |  |  |
|  |  +-------------------------------------------------------+  |  |
|  +----------------------------------------------------------+  |  |
+-------------------------------------------------------------------+
```

## 2. How the Cascade & Specificity Resolve Conflicts

When two CSS rules target the same element property, the browser resolves the winner in order:
1. **Inline `style="..."` or `!important`** (highest priority—avoid both in stylesheets so styles stay overridable).
2. **Selector Specificity** `(ID count, Class/Pseudo-class/Attribute count, Element count)`:
   - `#header` = `(1, 0, 0)`
   - `.card.featured` = `(0, 2, 0)`
   - `nav ul li a` = `(0, 0, 4)`
   Notice **one class `(0, 1, 0)` always beats ten element tags `(0, 0, 10)`!**
3. **Source Order:** When two selectors tie in specificity, the rule written **later** in the file wins.

**Professional Habit:** Keep specificity flat using single classes (`.card`, `.btn-primary`, `.btn-ghost`) instead of deep nested selectors like `#app main div.list ul li a`. Flat class specificity makes overriding styles predictable and eliminates `!important` wars.

## 3. Practice Exercises

1. Create two boxes (`width: 240px; padding: 24px; border: 4px solid;`)—one with `box-sizing: content-box` and one with `border-box`—and measure their rendered widths in Chrome DevTools Computed Box diagram.
2. Predict which color wins between `#nav .link`, `.header .nav-link.active`, and `nav a`, then verify in DevTools.

## Mastery Checklist

- [ ] Adds `box-sizing: border-box` at the top of custom stylesheets.
- [ ] Calculates `(ID, Class, Element)` specificity accurately without guessing.
- [ ] Keeps selectors flat (single classes) instead of reaching for `!important`.
