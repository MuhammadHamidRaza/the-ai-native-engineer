CSS feels unpredictable only when you treat spacing and positioning as trial-and-error magic instead of understanding **how the cascade resolves rules**, **how the Box Model computes element dimensions**, and **when Flexbox vs. CSS Grid owns layout**. Subchapter **06.2** replaces float/margin hacks with clean, predictable modern CSS.

## Lessons in Subchapter 06.2

1. **[06.2.1 Box Model, Specificity and Cascade](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-2-modern-css-and-responsive-layout/06-2-1-box-model-specificity-and-cascade):** `content`/`padding`/`border`/`margin`, why `box-sizing: border-box` is non-negotiable, specificity weights, and avoiding `!important`.
2. **[06.2.2 Flexbox and CSS Grid Systems](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-2-modern-css-and-responsive-layout/06-2-2-flexbox-and-css-grid-systems):** 1D alignment with Flexbox (`gap`, `justify-content`, `align-items`) vs. 2D responsive card grids with `grid-template-columns: repeat(auto-fit, minmax(...))`.
3. **[06.2.3 Responsive Breakpoints, Tokens and Dark Themes](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-2-modern-css-and-responsive-layout/06-2-3-responsive-breakpoints-tokens-and-dark-themes):** Mobile-first `@media (min-width: ...)`, CSS custom properties (`--surface`, `--ink`), and user-switchable light/dark themes.
4. **[06.2.4 Tailwind CSS v4 — Explicit Install & Verification](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-2-modern-css-and-responsive-layout/06-2-4-tailwind-css-v4-from-a-clean-setup):** What the `--tailwind` scaffold really installs; explicit Tailwind v4 setup (Vite plugin or Next.js PostCSS), the v3→v4 traps, a working styled component, and a production build check.
