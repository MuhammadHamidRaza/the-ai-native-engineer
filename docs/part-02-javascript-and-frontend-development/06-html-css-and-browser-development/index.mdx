Before React or Next.js enters the picture, every web application still compiles down to three browser primitives: **HTML** (structure and accessibility semantics), **CSS** (layout, spacing, typography, and responsive themes), and **DOM APIs** (events, network requests, and browser storage). Skipping these fundamentals produces brittle `<div>` soup, broken mobile layouts, inaccessible forms, and mysterious UI bugs.

**Chapter 06 (`16 Focused Hours`)** teaches how browsers actually turn HTML and CSS into pixels, and walks you through building, styling, inspecting, and debugging a responsive, keyboard-accessible page locally.

## Running Local HTML/CSS/JS Cleanly

Do **not** open local projects by double-clicking `index.html` (`file://...`) once you begin loading ES modules or calling `fetch()`—browsers block `file://` cross-file requests for security. Instead, serve your practice folder over HTTP:

```bash
# Option 1 (Node.js built-in npx server — zero setup)
npx serve .

# Option 2 (Python built-in HTTP server)
python3 -m http.server 5500
```

Then open `http://localhost:3000` (or `http://localhost:5500`) in Chrome or Edge and press `F12` to open **DevTools**.

## Chapter 06 Roadmap

- **06.1 Semantic HTML & Accessibility:** Document landmarks, forms, labels, native keyboard behavior, ARIA roles/live regions, and keyboard/screen-reader testing.
- **06.2 Modern CSS & Responsive Layout:** External stylesheets, `box-sizing: border-box`, cascade/specificity, Flexbox, CSS Grid, media queries, CSS variables, and dark themes.
- **06.3 The Browser DOM & Web APIs:** Safe DOM updates (`textContent`), event delegation, `fetch()`, `localStorage`, Chrome DevTools debugging, and a complete interactive responsive page build.
