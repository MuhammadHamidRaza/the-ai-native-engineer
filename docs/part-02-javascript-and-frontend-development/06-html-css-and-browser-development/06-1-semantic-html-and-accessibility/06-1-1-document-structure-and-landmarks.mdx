When a screen reader or search crawler reads your HTML, it does not look at font sizes or background colors—it reads the **tag names** and **Accessibility Tree**. Choosing semantic elements gives every user instant structural navigation without extra JavaScript.

## 1. Complete Semantic Document Shell

Save this starter `index.html` and inspect its landmarks:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>ShopCore — Online Storefront</title>
    <link rel="stylesheet" href="./styles.css" />
  </head>
  <body>
    <a class="skip-link" href="#main-content">Skip to main content</a>

    <header>
      <nav aria-label="Primary navigation">
        <a href="/">ShopCore</a>
        <ul>
          <li><a href="#features">Features</a></li>
          <li><a href="#pricing">Pricing</a></li>
        </ul>
      </nav>
    </header>

    <main id="main-content">
      <h1>Ship reliable software without chaos</h1>

      <section aria-labelledby="features-heading">
        <h2 id="features-heading">Core Capabilities</h2>
        <article>
          <h3>Fast Issue Triage</h3>
          <p>Filter tasks by owner, priority, and sprint status.</p>
        </article>
      </section>
    </main>

    <footer>
      <p>Built with semantic HTML5 landmarks.</p>
    </footer>
  </body>
</html>
```

## 2. Core Landmark & Element Rules

- **One `<main>` per page:** Lets keyboard and screen-reader users jump straight past repeated header navigation.
- **Logical Heading Hierarchy (`h1` -> `h2` -> `h3`):** Never pick `<h4>` purely because you want smaller text—style heading sizes in CSS and keep heading levels strictly sequential (`h1` once per page, no jumping `h1` directly to `h4`).
- **`<a href>` vs. `<button>`:** Use `<a>` when navigating to a URL or in-page anchor (`#features`). Use `<button type="button">` when triggering an in-page action (opening a modal, deleting a row, toggling theme).

## 3. Practice Exercises

1. Replace an existing `<div class="header">`, `<div class="menu">`, and `<div class="card">` layout with `<header>`, `<nav>`, `<main>`, and `<article>`, then open Chrome DevTools -> **Elements** -> **Accessibility** pane to verify the generated landmark tree.
2. Add meaningful `alt` descriptions to informative `<img>` tags and empty `alt=""` to purely decorative icons so screen readers skip noise.

## Mastery Checklist

- [ ] Includes `lang="en"`, `meta charset="UTF-8"`, and responsive `viewport` meta tag.
- [ ] Keeps heading levels (`h1` -> `h2` -> `h3`) ordered with zero skipped levels.
- [ ] Uses `<a>` for navigation and `<button>` for actions—never clickable `<div>` elements.
