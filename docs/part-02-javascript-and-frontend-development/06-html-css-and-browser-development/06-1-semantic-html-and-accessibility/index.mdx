Writing `<div class="btn" onclick="...">` instead of `<button type="button">` silently breaks keyboard navigation, screen-reader announcements, and form submission all at once. Semantic HTML gives assistive technologies, search engines, and browsers rich meaning for free before you write a single line of JavaScript.

## Lessons in Subchapter 06.1

1. **[06.1.1 Document Structure and Landmarks](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-1-semantic-html-and-accessibility/06-1-1-document-structure-and-landmarks):** `<!DOCTYPE html>`, `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`, heading order, and link vs. button rules.
2. **[06.1.2 Forms, Validation and Keyboard Navigation](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-1-semantic-html-and-accessibility/06-1-2-forms-validation-and-keyboard-navigation):** Explicit `<label for="...">`, input types, HTML validation attributes, focus rings (`:focus-visible`), and Tab order.
3. **[06.1.3 ARIA Semantics and Screen Readers](/book/part-02-javascript-and-frontend-development/06-html-css-and-browser-development/06-1-semantic-html-and-accessibility/06-1-3-aria-semantics-and-screen-readers):** The First Rule of ARIA, `aria-label`, `aria-expanded`, `aria-live` status updates, and practical accessibility testing in Chrome DevTools.
