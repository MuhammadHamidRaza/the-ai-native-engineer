Two subtle JSX habits trip up almost every new React developer: using array index (`key={i}`) on dynamic lists, and rendering `{items.length && <List />}` when `items` is empty. Both compile cleanly and create bizarre UI glitches.

## 1. Lists & Why Stable `key` Props Are Non-Negotiable

When rendering `.map()`, React needs a unique, persistent **`key`** on each sibling element so it can match DOM nodes (and any input focus or checkbox state inside them) across inserts, sorts, and deletions:

```tsx
interface Task {
  id: string;
  title: string;
}

export function TaskList({
  tasks,
  onDelete,
}: {
  tasks: readonly Task[];
  onDelete: (id: string) => void;
}) {
  if (tasks.length === 0) {
    return <p className="text-sm text-slate-500">No tasks yet. Add one above!</p>;
  }

  return (
    <ul className="space-y-2">
      {tasks.map((task) => (
        <li key={task.id} className="flex items-center justify-between border p-2 rounded">
          <span>{task.title}</span>
          <button type="button" onClick={() => onDelete(task.id)}>
            Delete
          </button>
        </li>
      ))}
    </ul>
  );
}
```

**Why `key={index}` breaks dynamic lists:** If you delete item `0`, the old item `1` becomes index `0`. React thinks DOM node `0` is still the same item and leaves stale input text or unchecked boxes attached to the wrong row! Also never generate `key={Math.random()}` during render—that forces React to destroy and recreate every DOM node on every keystroke. Always use a stable entity ID (`task.id`).

## 2. Conditional Rendering & the `0` Trap

- **Buggy:** `{tasks.length && <TaskList tasks={tasks} />}` renders the literal number **`0`** onto the page whenever `tasks` is empty!
- **Safe:** Use an explicit boolean (`{tasks.length > 0 && ...}`) or a ternary (`{tasks.length > 0 ? <TaskList ... /> : <EmptyState />}`).

## 3. Controlled Forms in React

Bind an input's `value` to React state and update it via `onChange` so React remains the single source of truth:

```tsx
import { useState, type FormEvent } from "react";

export function NewTaskForm({ onAdd }: { onAdd: (title: string) => void }) {
  const [title, setTitle] = useState("");

  function handleSubmit(e: FormEvent) {
    e.preventDefault();
    const trimmed = title.trim();
    if (!trimmed) return;
    onAdd(trimmed);
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit} className="flex gap-2">
      <label htmlFor="task-title" className="sr-only">Task title</label>
      <input
        id="task-title"
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="Add a task..."
      />
      <button type="submit" disabled={!title.trim()}>
        Add
      </button>
    </form>
  );
}
```

## 4. Practice Exercises

1. Combine `NewTaskForm` and `TaskList` inside `src/App.tsx`, prepend a new task using `crypto.randomUUID()`, and verify deleting middle items keeps all remaining rows intact.
2. Intentionally test `{tasks.length && <p>Has items</p>}` with an empty array to see `0` appear on screen, then fix it to `{tasks.length > 0 && ...}`.

## Mastery Checklist

- [ ] Uses stable record IDs (`key={item.id}`)—never `index` or `Math.random()`—for dynamic lists.
- [ ] Guards `&&` conditional renders with explicit booleans (`count > 0`) to prevent stray `0`s.
- [ ] Handles empty states cleanly and builds controlled inputs with `<label>`.
