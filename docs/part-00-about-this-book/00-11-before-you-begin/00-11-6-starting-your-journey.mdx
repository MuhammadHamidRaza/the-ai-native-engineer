### Your First 2-Minute Programming Exercise (`hello.js` & `hello.py`)

Before moving to Part 01, prove you can create, run, and verify a tiny real program in both runtimes right inside `~/code/ai-native-engineer/journal`:

```bash
cat << 'EOF' > hello.js
const engineer = process.argv[2] || "AI-Native Builder";
console.log(`Hello, ${engineer}! Node.js ${process.version} is ready.`);
EOF

cat << 'EOF' > hello.py
import sys
engineer = sys.argv[1] if len(sys.argv) > 1 else "AI-Native Builder"
print(f"Hello, {engineer}! Python {sys.version.split()[0]} is ready.")
EOF

node hello.js "Alex"
python3 hello.py "Alex"
```

Expected output:

```text
Hello, Alex! Node.js v26.x.x is ready.
Hello, Alex! Python 3.14.x is ready.
```

Try changing `"Alex"` to your own name and observe how command-line arguments (`process.argv[2]` in Node.js and `sys.argv[1]` in Python) pass input directly into a running program.

## Five Grounding Commitments to Carry Forward

Before clicking into Chapter 01, lock these five simple habits in place:
1. **Manual reps first ([00.6.3](/book/part-00-about-this-book/00-6-teaching-and-practice-method/00-6-3-manual-practice)):** Never let an AI prompt solve a foundational exercise you have not wrestled with cleanly on your own.
2. **Trace reality before guessing:** Open browser DevTools, read server logs, inspect `git diff`, and verify version outputs rather than swapping random lines hoping errors vanish.
3. **Protect small vertical slices:** Build tiny working flows completely (data → logic → validation → UI → test) rather than sprawling broken half-skeletons.
4. **Stay curious beneath abstractions:** When `React`, `FastAPI`, `PostgreSQL`, or an AI agent surprises you, look one layer deeper instead of blindly pasting fixes.
5. **Measure progress in verified systems built:** Keep `PROGRESS.md` honest (`00.11.5`) and ship everything cleanly (`Think. Build. Solve. Ship.`).

## Quick Recovery Checks If the Smoke Test Fails

Should your initial `git init` / `git commit` command sequence stumble on day one, diagnose calmly instead of uninstalling everything:
- **If `git: command not found` appears:** Install Git directly per [00.11.2](/book/part-00-about-this-book/00-11-before-you-begin/00-11-2-setting-up-your-development-environment) and restart your shell terminal completely so updated `PATH` directories reload cleanly.
- **If `git commit` refuses with `Please tell me who you are`:** Configure `git config --global user.name` and `git config --global user.email`, verify via `git config --list`, and re-run only the commit command.
- **If permissions fail inside Windows WSL 2:** Confirm `pwd` prints `/home/<username>/code/ai-native-engineer/journal`, **not** `/mnt/c/Windows/System32`. Running Linux tooling inside Windows system directories produces permission failures immediately.
