The core curriculum of **The AI-Native Engineer** consists of exactly **10 Curriculum Parts**, **42 Chapters**, and **638 focused learning hours**, supported by **Appendices A–E** for client delivery playbooks, career preparation, and rapid technical reference. **Part 00 — About This Book** stands *before* Part 01 as architectural orientation and learning preparation; it does not alter the 10-part curriculum or add to the 638 hours.

Look closely at the distribution of hours across those ten parts: nearly two-thirds of the entire book (**394 hours across Parts 01–06**) builds uncompromising mastery of deterministic software engineering, databases, backends, cloud deployment, and security before investing **168 hours across Parts 07–08** in AI-native workflows, RAG, agents, MCP, automation, and production AI evaluation—followed by **76 hours across Parts 09–10** converting those technical capabilities into client impact, products, and one deployed capstone.

## 2. Why Every Part Exists and What Each Unlocks

### Part 01 — Foundations (`26 Hours`)
Before writing framework components, you establish crisp mental models of CPU/RAM/disk/process execution, DNS/TCP/TLS/HTTP request flows, structured root-cause decomposition, terminal fluency, Git version control, and disciplined debugging. Skipping this costs beginners months later.

### Part 02 — JavaScript & Frontend Development (`92 Hours`)
Frontend software is full software engineering, not merely styling boxes. You invest **28 hours** mastering JavaScript closures, prototypes, event loops, and async behavior before **12 hours** of strict TypeScript, **16 hours** of semantic HTML/CSS/browser internals, **22 hours** of stateful React architecture, and **14 hours** of Next.js server/client rendering and API boundaries.

### Part 03 — Python Development (`40 Hours`)
Python sits at the center of modern AI backends, data ingestion, document processing, and agent SDKs. Across **40 hours**, you progress from core types, comprehensions, virtual environments, typing, and object models (`26h`) into FastAPI web services, file parsing, HTTP clients, and operational automation (`14h`).

### Part 04 — Databases, Backend & Full-Stack Development (`124 hours`)
Notice **Part 04** is the **largest single Part in the book at `124 hours`** — 34% larger than Part 02's `92h`, and the load-bearing foundation for everything after it. Real software breaks around persistent state, concurrency, and teamwork. You design normalized relational schemas (`Ch 11`), master SQL queries, joins, constraints, PostgreSQL internals, and MongoDB document patterns (`Ch 12`), build Node.js backends (`Ch 13`), enforce Git PR workflows and automated Vitest/Pytest suites (`Ch 14`), and integrate a full authenticated multi-tier application (`Ch 15 - 38h`).

### Part 05 — Deployment, Cloud & DevOps (`62 Hours`)
Shipping software safely means understanding where code runs. You learn Linux administration and networking (`Ch 16`), DNS, TLS certificates, and reverse proxies (`Ch 17`), multi-container Docker packaging (`Ch 18`), automated CI/CD test/deploy workflows (`Ch 19`), and production logging, backups, and incident operations (`Ch 20`).

### Part 06 — System Design & Production Quality (`50 hours`)
Moves you beyond single-feature thinking into system-wide judgment: modular boundaries and ADRs (`Ch 21`), OWASP security hardening, rate limiting, retries, and OpenTelemetry-style observability (`Ch 22`), caching, queues, and throughput scaling (`Ch 23`), and query plan optimization (`EXPLAIN`) plus zero-downtime database migrations (`Ch 24`).

### Part 07 — AI-Native Software Development (`40 hours`)
Bridges deterministic engineering into the AI era cleanly: understanding model tokenization, context limits, streaming, and structured outputs via server-side APIs (`Ch 25`), engineering prompts and system specs as deterministic versioned interfaces (`Ch 26`), and turning AI coding assistants into high-precision, spec-driven collaborators (`Ch 27`).

### Part 08 — AI Applications, Agents, MCP & Automation (`128 Hours`)
Representing over one-fifth of the entire curriculum (`128h`), Part 08 covers production AI engineering without shortcuts: hybrid permission-filtered RAG (`Ch 28`), agent vs. workflow design (`Ch 29`), Python OpenAI Agents SDK (`Ch 30`), state/memory/guardrails (`Ch 31`), Model Context Protocol servers & clients (`Ch 32`), n8n operational workflows (`Ch 33`), asynchronous AI workers (`Ch 34 — 20h`), multi-agent coordination (`Ch 35`), and production evaluation harnesses & FinOps (`Ch 36`).

### Part 09 — Career, Client Work, Products & Startups (`40 Hours`)
Translates technical skill into real-world leverage across engineering teams (`Ch 37`), job readiness and portfolio positioning (`Ch 38`), FDE client discovery, proposals, and delivery (`Ch 39`), MVP scoping (`Ch 40`), and early-stage technical product launches (`Ch 41`).

### Part 10 — Integrated Capstone (`36 Hours`)
One dedicated **36-hour** engineering build (`Chapter 42`) taking a genuine operational problem from initial **Listen & Map** notes through schema design, backend/frontend code, grounded AI/agent orchestration, automated tests + AI evals, Docker cloud deployment, and complete handover documentation.

## 3. How Appendices A–E Support the 10 Parts

Sitting cleanly outside the 10 curriculum parts, **Appendices A–E** function as your permanent field kit (`/book/appendix`):

- **Appendix A — Complete Client Acquisition Playbook:** Structured discovery, scoping, pricing, and client proposal execution.
- **Appendix B — Practical Client Outreach Rules and Templates:** Honest, non-spammy outreach workflows and communication templates.
- **Appendix C — Client Hunting Practice Workbook:** Drills for practicing discovery and problem framing before live calls.
- **Appendix D — Job Search and Career Resources:** Role checklists, interview preparation, and portfolio review rubrics.
- **Appendix E — Developer Reference Materials:** High-frequency CLI, Git, SQL, Docker, HTTP status, and debugging cheatsheets.

## 4. Why the Parts Interlock Instead of Standing Alone

No serious system uses only one curriculum part. **Part 04's** relational schemas enforce the row-level permissions inside **Part 08's** RAG queries; **Part 05's** Docker and TLS discipline protects **Part 08's** MCP servers and webhooks; **Part 06's** verification mindset powers **Part 07's** AI-assisted code reviews; and **Part 09's** FDE lifecycle focuses **Part 10's** capstone onto solving a real human bottleneck.

## Key Takeaways

- Every hour in the **10-part, 42-chapter, 638-hour** curriculum is allocated proportionally to real production engineering complexity.
- Deterministic full-stack, data, cloud, and system-quality mastery (`394h`) directly underpins production AI engineering (`168h`) and field/capstone execution (`76h`).
- **Appendices A–E** provide repeatable operational playbooks and reference lookup alongside the core parts.
